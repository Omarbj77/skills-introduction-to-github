# Guía para principiantes: espacio de práctica en GitHub

Esta guía está pensada para personas que empiezan desde cero. La idea es usar este repositorio como **laboratorio de práctica** para aprender GitHub paso a paso y luego aplicar lo mismo en otros proyectos.

## 1) Objetivo de este repositorio de práctica

Crear un entorno simple donde puedas practicar:

1. Crear ramas
2. Hacer commits
3. Abrir Pull Requests (PR)
4. Revisar y fusionar cambios
5. Organizar tareas con Issues

> **Rama (branch):** copia de trabajo de tu proyecto para hacer cambios sin tocar `main`.
> **Commit:** guardado de cambios con mensaje.
> **Pull Request (PR):** propuesta para integrar cambios de una rama hacia otra.

## 2) Ruta recomendada (en orden)

1. Completa el ejercicio base de este repositorio (branch, commit, PR, merge).
2. Crea una rama nueva llamada `practica/herramientas`.
3. Añade un archivo de pruebas, por ejemplo `docs/practica.md`.
4. Haz al menos 3 commits pequeños (no uno grande).
5. Abre un PR explicando qué aprendiste y por qué.
6. Fusiona el PR y elimina la rama.

## 3) Herramientas de GitHub para empezar fuerte

- **Issues:** para anotar tareas o dudas.
- **Pull Requests:** para revisar cambios antes de fusionar.
- **Actions:** para automatizar validaciones (tests, checks).
- **Projects:** para organizar tareas visualmente (To Do / In Progress / Done).
- **Discussions:** para preguntas y aprendizaje colaborativo.

## 4) Mini glosario (sin tecnicismos)

- **Repositorio:** carpeta de proyecto en GitHub.
- **Fork:** copia de otro repositorio en tu cuenta.
- **Clone:** descargar el repositorio a tu computadora.
- **Merge:** unir cambios de una rama a otra.
- **Review:** revisión de código antes de aprobar cambios.
- **Workflow:** automatización de pasos (por ejemplo, ejecutar tests).

## 5) Buenas prácticas para novatos

- Haz cambios pequeños y frecuentes.
- Usa mensajes de commit claros (ejemplo: `docs: agrega glosario inicial`).
- Escribe en cada PR: objetivo, cambios, y cómo probarlos.
- No tengas miedo a equivocarte: usa ramas para experimentar.

## 7) Siguiente paso sugerido

Si no tienes un proyecto definido todavía, úsalo así:

- Crea una carpeta `docs/`
- Documenta una herramienta por archivo (Issues, PR, Actions, etc.)
- Incluye ejemplos reales (capturas, comandos, errores comunes)
- Repite el flujo: rama -> commit -> PR -> revisión -> merge

Con eso, este repositorio te servirá como plantilla para ayudar a otras personas que también comienzan.
